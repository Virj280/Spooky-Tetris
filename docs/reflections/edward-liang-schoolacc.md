My main role in this project was to design features and fix existing bugs, such
as spawning bats at the right elevation and preventing tetrominoes from going
over the sides of the board; I also made art for the background. I had
collaborated well with my team leader to get bugs patched. I also made the code tour and test plan. However, my
debugging was very unoptimized, since I mostly worked locally in Visual Studio
Code and confusingly copy & pasted new sections of code to a version of the .js
that other people had worked on.


GitHub was helpful in that we could track our to-do list, milestones, and
current issues. However, it was annoying that only one person could edit the .js
at a time, since I would have to adjust my locally written code to be put in a
file that was different from when I started working on it.


If I could do something differently, I would make a schedule of all the features
we needed to add and by which dates, so that we could keep track of what we
needed to do instead of always fixing and improving upon last class’s
achievements. I would also suggest that my teammates should immediately create
side branches to commit codes and use pull requests instead of confusingly
committing to the same master branch.
